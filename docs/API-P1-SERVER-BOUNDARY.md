# API-P1 server boundary

API-P1 uses Fastify 5.11.0 only as transport. `createApi` receives injected `AuthVerifier`, SEC-P2 user resolver, secure birth-profile service, SEC-P6 reading service, and optional entitlement service; it creates no pool, provider, KMS, or crypto dependency.

Routes are `GET /health`, `GET /ready`, `GET /v1/me`, profile create/list/get, reading create/get, reading replay, and optionally entitlements. Requests require an injected verifier to turn an Authorization credential into a verified principal. Route code never decodes a JWT, trusts client owner/user identifiers, or selects an engine profile/ruleset.

`POST /v1/readings` currently creates only a `CAREER` reading. Its public body is `{ birthProfileId, domain: 'CAREER' }`; a 1–128 character `Idempotency-Key` header is required. The server fixes the reading instant to its injected clock and the locale to `en-IN`; callers cannot select either. Request bodies are limited to 16 KiB. Generation is synchronous, persists the immutable encrypted record, and consumes one active user-scoped `CAREER` entitlement only in the final insert transaction. An idempotent retry returns the existing record without another consumption. Responses use allowlisted DTOs and include only safe request IDs; ciphertext, nonces, keys, KMS references, DB rows, SQL/RLS details, and auth subjects are omitted. Invalid authentication is 401; hidden ownership failures are 404; invalid input is 400; exhausted entitlement is 403.

`GET /v1/readings` is an authenticated, read-only Reading Center surface. It returns at most the 50 newest records owned by the caller, ordered by `createdAt` descending and then `readingId` ascending. An optional `birthProfileId` filter is ownership-checked before listing. Each summary is limited to `readingId`, `birthProfileId`, `domain`, `status`, `createdAt`, `readingInstant`, and `locale`; no reading content or encrypted payload is included. `GET /v1/readings/:id` is also authenticated and ownership-checked, returns the same safe metadata plus the already persisted rendered content, and may decrypt that record after ownership is verified. Neither GET endpoint creates or regenerates a reading, calls replay, mutates a profile, or consumes entitlement. The only currently supported public reading domain remains `CAREER`; these endpoints are intended for the Flutter Reading Center.

`GET /v1/me/entitlements` is an authenticated, read-only status surface for the currently usable `CAREER` reading capability. It returns only `{ entitlements: { career: { eligible } } }`, where eligibility reuses the same server-clock active-grant selection authority as a new `POST /v1/readings`: the authenticated application user's first active positive-quantity `CAREER` grant, ordered by valid-from then entitlement ID. The endpoint exposes neither grant IDs nor quantities, expiry, payment provenance, or user identity. It does not reserve, consume, or mutate an entitlement and provides no purchase/payment capability. It is informational only: `POST /v1/readings` remains the final transactional authority, so eligibility may become stale if another request consumes the last entitlement before POST.

Production CORS must use an injected allowlist—never authenticated wildcard CORS. Bearer-token APIs do not use cookie CSRF semantics; reassess if cookies are introduced. Rate limiting, security headers, a production Supabase verifier, and a production KMS provider are deferred. The API remains portable and does not select hosting or package Swiss runtime. Production KMS provider: **UNDECIDED**.
